# 0.4.0 GitHub 上传准备计划

此计划在本轮源码修改前建立。目标是提供可在 GitHub 建仓上传的源码版本，保留历史交付物；不创建远程仓库、不上传、不加入 GitHub Actions，也不发布 npm。

## 验收标准与实施顺序

1. **可靠性**：为页面内 CSS 校验和溢出测量增加明确超时；清理失败时保存已采集报告并返回执行错误；加入真实 Chromium 卡住页面及清理失败回归用例。
2. **可重复安装**：固定已验证的直接依赖，补 npm 锁文件，保留 pnpm 锁文件及其可用性。下载并校验官方 Node 22 运行包，在干净源码目录执行 `npm ci`、浏览器安装、类型检查、构建、测试和 smoke test。
3. **仓库体验**：提供统一的 `npm run check`，验证 CLI 帮助、版本及错误退出码；完善双语 README、贡献指南、变更记录、Issue/PR 模板和上传说明。忽略依赖、构建、缓存、审计产物及本地环境文件。
4. **上传文件验证**：在本地初始化 Git，核对待上传文件和忽略规则；验证 Markdown 本地链接、空白差异及源码包清单。源码包不含 `.git`、node_modules、dist、缓存、运行日志或原始审计报告。

## 已发现的具体问题

- 浏览器内的 `page.evaluate` 不受当前默认超时约束；阻塞页面可使测量一直等待，已在真实 Chromium 复现。
- 浏览器关闭异常会在报告写入前抛出，丢失已采集结果。
- README 以 npm 为主要安装方式，但尚无 npm 锁文件。
- 文档展示的 `--output ./reports` 目录尚未忽略。
- 目前只在 Node 24 验证，尚缺 Node 22 的实际安装及运行证据。

## 范围

保留单 URL、四种固定视口、截图、JSON、就绪选择器和唯一 CSS 路径的现有功能。全局清理错误仅通过兼容旧报告的可选字段记录。版本为 0.4.0，包继续 `private` 以防 npm 误发布，MIT 源码可公开。

上传需要真实远程仓库地址；本轮不伪造作者身份或 GitHub 地址。没有 Git 作者配置时保留可上传源码与操作说明，不冒名创建提交。

新增可选顶层 `errors` 只在整体清理错误时写入，保留旧报告兼容；`summary.errors` 仍统计视口执行错误。页面内求值使用配置超时，浏览器和上下文清理各有 5 秒时限。

源码包从经过核对的 Git 索引树生成，保留 MIT、双语 README、贡献指南、变更记录、Issue/PR 模板和实际上传说明。历史交付包保留；新源码包不含生成数据。完整运行证据单独保存在交付目录，不进入源码包。

本地 Git 已初始化为 main，源码已暂存；本机未配置作者身份，没有伪造身份创建提交，没有配置远端或执行上传。实际提交和上传时使用本人的 Git 身份及真实仓库地址，步骤见 github-upload.md。

本轮开发验收项全部完成。未单独验证 Linux/macOS；仍不实现 AI 自动修复、HTML dashboard、GitHub Actions 或 npm 发布。
