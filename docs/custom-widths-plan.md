# 0.5.0 开发计划：自定义检查宽度

在实现前建立本计划，继续保留 GitHub 可上传的纯源码交付方式和原有功能范围。

## 目标与约定

- CLI 增加 `--widths <list>`，例如 `--widths "320,768,1920"`；API 增加可选的 `widths?: number[]`。
- 允许 1～8 个唯一宽度，每项为 240～3840 CSS 像素的整数，保留输入顺序。高度统一 900，设备缩放比例仍为 1。
- CLI 使用逗号分隔，可去除各项首尾空格；只接受十进制数字。空项、尾逗号、小数、科学计数、带单位数字、越界、重复及过多项均拒绝。
- 允许十进制前导零，但转换后再检查重复，例如 `0360,360` 被拒绝。API 不将字符串转换为数字。
- 未传入选项时仍使用 360/390/768/1440px。仅显式传入时向 JSON 的 `options` 增加可选 `widths`，包括显式指定默认列表的情形。`schemaVersion` 仍为 `1.0.0`，旧报告可继续解析。
- 截图沿用 `screenshots/<width>.png`，禁止重复宽度以避免同一运行内覆盖。统计和检查次数以实际宽度列表为准。
- 无效输入在启动浏览器或创建输出目录前返回退出码 2；既有错误优先级及清理行为保留。

## 实施顺序

1. 补充参数与报告兼容测试，覆盖边界、数量、重复、非法语法及未设置情况。
2. 在配置层集中解析和校验，将参数接入 CLI、审计循环与报告。
3. 增加真实浏览器回归：不排序的自定义列表、单视口、同一运行的通过/失败混合、截图数量及 PNG 尺寸。
4. 扩展实际 CLI smoke 场景，保留原有默认场景；更新双语 README、变更记录及示例。
5. 在 Node 24 运行完整检查，在 Node 22 的干净源码目录用锁文件安装并运行统一检查。
6. 复查源码包、锁文件、Git 忽略及本地文档链接，保留历史交付物，不推送远端。

## 不增加的范围

本轮不加入自定义高度、设备/浏览器预设、配置文件、失败策略、报告比较、AI 自动修复、HTML dashboard、GitHub Actions 或 npm 发布。

实现前先运行配置/报告相关的 37 项用例，其中 5 项失败，确认旧版本缺少自定义宽度接受与报告持久化行为；实现后新增与既有测试全部通过。相较 0.4.0，新增 51 项测试及 4 个 smoke 场景。

不传宽度时仍生成原有四种视口，JSON 不添加 widths；显式列表（包括默认列表）保留在 options.widths，schemaVersion 仍为 1.0.0。无效宽度在启动浏览器和创建目录前拒绝，输出文件不互相覆盖。

新的源码包由本地 Git 索引树导出，不含依赖、dist、缓存或审计数据。运行证据另存交付目录，历史交付包保留。没有配置远端、创建个人身份提交或推送 GitHub。

本轮验收项无未完成项。未单独验证其他操作系统；本轮仍不包含自定义高度、设备预设、配置文件、失败策略、报告比较、AI 自动修复、dashboard、GitHub Actions 或 npm 发布。
