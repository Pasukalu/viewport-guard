# 1.0 完整版计划

本计划在本轮实现前建立。本轮目标是交付完整、经过实际验证的 1.0 项目，并上传到用户的 GitHub 账户。用户已确认扩大原先的范围，加入鲸鱼娘主题本地可视化报告；继续不做 AI 自动修复、GitHub Actions 或 npm 发布。

## 交付范围

1. **配置文件**：显式 `--config <file>`，仅接受严格校验的 JSON。优先级为默认值、配置文件、显式 CLI 参数。配置文件中的相对路径相对配置文件目录，CLI 路径相对当前目录。URL 继续由位置参数传入。
2. **失败策略**：`--fail-on all|none|overflow,console,pageerror,request`。原始发现、视口状态和统计保留；额外记录策略执行结论。被忽略的问题仍被收集并展示，执行错误始终退出 2。
3. **基线比较**：`compare <baseline.json> <current.json>`，以及审计时可选的 `--baseline`。按目标 URL、视口集合、失败策略检查兼容性，比较新增、消失、溢出加重/改善，忽略时间戳、截图路径、耗时、堆栈和快照 CSS 路径。新增或加重退出 1，无回归退出 0，不兼容/执行失败退出 2。
4. **离线 HTML 报告**：`audit --html` 和 `report <report.json>`。生成自包含文件，展示视口截图、溢出证据、三类错误、策略结论及可选比较摘要；不依赖 CDN，不执行报告中的页面字符串，严格限制本地截图读取。
5. **项目整体设计**：以用户确认的 DeepSeek 蓝发女仆鲸鱼娘二创方向统一吉祥物、深海蓝/白视觉、项目介绍、README 和 HTML 报告。新生成项目专用图，保留来源和非官方说明，角色素材与代码 MIT 许可分开说明。
6. **完整交付和上传**：保留既有默认行为与旧 JSON 读取，补示例配置、全套测试、双语文档、品牌说明和版本记录。在 Node 22/24 验证干净安装及完整流程，核对源码和素材后，创建或选择正确的 GitHub 仓库、上传并验证远端页面。

## 技术边界

- 配置不执行 JavaScript，不增加隐式搜索、爬虫、登录自动化或插件系统。
- 单 URL、最多八种宽度、高度 900、Chromium、PNG/JSON 的既有基础保留。
- 默认失败策略与现有行为一致；新增 JSON 字段保持可选，旧报告继续读取。
- 原始审计事实与策略判断分开，HTML 对目标 URL、错误文本和节点选择器等不可信内容转义。
- 基线输入必须完整且兼容，不静默忽略缺失视口，不使用 AI 模糊比较。
- 图片为新生成的非官方项目二创，不直接复用社区图库文件或声称 DeepSeek 官方背书。
- GitHub 上传得到本次用户指令授权；只有身份、登录或访问权限确实缺失时请求必要协助，不重复确认已授权步骤。

## 实施顺序

先确定模块接口并行开发配置/CLI、策略与比较、离线报告、品牌素材及文档；随后整合运行审计、报告生成和基线工作流。先完成可检查的本地结果，最后执行远端上传。
